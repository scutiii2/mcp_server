# docs/

Two kinds of documentation, kept separate:

- **[`capabilities/`](capabilities/README.md)** - long-form, maintained
  technical documentation for capabilities, tracking live code
  (each file carries its own version/last-updated header) - deeper
  narrative than a capability's own `README.md`/`STATIC-GUIDELINES.md`.
- **[`superpowers/`](superpowers/README.md)** - point-in-time specs and
  implementation plans from the `superpowers` skill workflow, written
  before a feature was built - not maintained after it ships.

For how the server actually works today, start with the root
[`../README.md`](../README.md) and each capability's own README.
