# Prompt suggestion in the chat box

Date: 2026-10-08. Status: draft, awaiting review.

## Goal

After the assistant finishes an answer, the chat box shows a predicted next
prompt as its placeholder. Pressing Tab on an empty box fills it in. The user can
edit it before sending. This matches the prompt suggestion in Claude Code.

A second feature (clickable questions the agent asks the user) is out of scope.
It gets its own spec.

## Decisions

- The suggestion is generated by one LLM call after each answered turn.
- It reaches the browser through a new on-demand endpoint. The turn/SSE event
  contract does not change, so `chat_cli` is unaffected.
- Each account has a server-side preference, `prompt_suggestions`, default on.
  When it is off, ember_api makes no call. The setting is enforced on the
  server, not only hidden in the UI.

## ember_api

### Preference

- New column `accounts.prompt_suggestions` (`Boolean`, `NOT NULL`,
  `server_default` true). Needs an Alembic migration
  (`python -m scripts.migrate_db revision "account prompt suggestions"`).
- `AccountOut` (`src/routes/auth.py`) exposes `prompt_suggestions`, so
  `GET /api/auth/me` already delivers it to the browser's auth store.
- New `PATCH /api/account/preferences` with body `{prompt_suggestions: bool}`
  (JSON only). Gate: `Depends(current_account)`. It returns the updated
  `AccountOut`. It writes an audit entry,
  `logs.action(account, "account.preferences", "prompt_suggestions on|off")`.

### Suggestion service

New `src/services/suggestions.py`, same shape as `services/summarization.py`:

- `build_prompt(question, answer)`: asks for the single most likely next
  message the user would type, in the user's voice, at most 120 characters,
  plain text, no quotes, no preamble. Returns the exact token `NONE` when no
  natural follow-up exists. Inputs are the last user message and the last
  assistant answer, each truncated (about 2,000 characters).
- `async suggest(gateway, url, caller, question, answer) -> SuggestionOutcome | None`
  calls `gateway.interpret`. It collapses whitespace, strips surrounding quotes,
  cuts at the first newline, and enforces the 120-character cap. It returns
  `None` for empty output, `NONE`, or an `AgentCallError`. It never raises to
  the route.
- Usage is recorded as kind `suggestion` through the same accounting path as
  `_record_usage` in `turns.py`, so the cost shows in the Usage page.

### Route

`GET /api/chats/{chat_id}/suggestion` in `routes/chats.py`.

- Gate: `Depends(require_permission("chat.use"))`. The chat must belong to the
  caller, otherwise 404.
- Returns `{text: string | null}`.
- Returns `{text: null}` without any LLM call when: the preference is off; the
  chat has no assistant message; the last assistant message is cancelled or an
  error; a turn is currently running for the chat; or the last exchange has a
  user message under 3 characters.
- The route reads the last user/assistant pair from the saved chat, so a
  reload or a second device gets the same result.

- Route tests: 401 logged out, 403 without `chat.use`, 404 for another

## ember_web

- `api/chatsClient`: `suggestion(id)` returns `{text: string | null}`.
- `api/authClient` (or the existing account client): `setPreferences({...})`.
  The auth store updates `account.prompt_suggestions` from the response.
- `stores/chat.ts`:
  - New state `suggestion: string | null`.
  - When a turn finishes with outcome "answered" (not "stopped", not error),
    and `account.prompt_suggestions` is true, fetch the suggestion. Only apply it
    if the chat id and turn sequence still match when the response arrives.
  - Clear the suggestion when the user types, sends, or switches chats, and when
    the preference is turned off.
  - Also fetch when an existing chat is opened and no turn is running, so
    reopening a chat shows its suggestion. A failed fetch is silent.
- `components/ChatInput.vue`:
  - New prop `suggestion?: string | null`.
  - The placeholder is the suggestion while the draft is empty and a suggestion
    exists. Otherwise the current placeholder.
  - At the top of `onKeydown`: Tab, draft empty, suggestion present, no
    `#`/`/` suggestion list open, no IME composition, then `preventDefault()`,
    set `draft` to the suggestion, and emit `suggestion-used` so the store
    clears it. Enter does not accept a suggestion on an empty box.
  - A faint hint ("Tab to accept") is shown next to the box on wide screens,
    using theme tokens only.
- `views/SettingsView.vue`: one `ToggleSwitch small` row, "Suggest next prompt",
  in the existing chat group. It applies instantly, like the other toggles.
- `e2e/fakeApi.ts`: add `GET /api/chats/:id/suggestion` and the `PATCH`.

### Tests (Vitest)

- Store: fetch on answered, none on stopped, stale response dropped after a
  chat switch, cleared on typing, no fetch when the preference is off.
- ChatInput: placeholder shows the suggestion; Tab fills the draft; Tab is
  ignored with a non-empty draft; Tab still completes `#` templates when that
  list is open.
- SettingsView: the toggle calls the client and updates the store.
- `npx vue-tsc -b --noEmit` prints nothing, `npx vite build` passes, delete
  `dist/`.

## Failure behaviour

Any failure (agent down, empty reply, timeout) yields `{text: null}` and the
box keeps its normal placeholder. A suggestion never delays or blocks an answer,
because it is fetched after the turn has ended.

## Not included

- Choosing a cheaper model for suggestions. It uses the agent's `interpret()`
  as the summarizer does today.
- Streaming the suggestion.
- Suggestions in `chat_cli`.
